# Associate — Prompt 3: The Soul Layer
## Continuity, Inevitability, and the System That Operates Without You

> **Purpose:** This is not a feature prompt. This is the correction prompt. It fixes the fundamental gap in Prompts 1 and 2: the demo still feels like a tool responding to a user. Associate's core conviction is that **it exists continuously — even when the lawyer is not there.** This prompt rewires the demo at the architecture level. Apply on top of Prompts 1 and 2. Every section here overrides or extends the equivalent section in prior prompts.
>
> **The single test:** After this prompt is applied, a person watching the demo should feel mild anxiety at the thought of *not* using Associate. Not because it's impressive. Because leaving would mean losing the compounding advantage it has already built.

---

## WHAT CHANGES FUNDAMENTALLY

### The Old Mental Model (what Prompts 1 and 2 built)
```
User opens Associate
→ User takes action
→ Associate responds
→ Session ends
```

### The Correct Mental Model (what this prompt builds)
```
2:47 AM — Agent reads new SEBI circular. Updates 2 matters.
5:14 AM — eCourts cause-list pulled. 3 matters listed tomorrow.
6:04 AM — Counter-affidavit ingested. Rejoinder drafted. 
           Contradiction mapped. Cross-exam questions ready.
6:12 AM — Morning brief written.
7:15 AM — Lawyer opens Associate.
           Everything is already done.
           The lawyer reads. Then decides.
```

The demo must make the viewer *feel* the time gap. The agent was here all night. The lawyer arrived to a workspace that had been operating without them.

## PART 3 — REDLINE INTELLIGENCE (NEW OPEN FEATURE)

### What it does — full specification

When a contract is uploaded to a matter, Associate:

1. **Reads the full contract** and identifies every clause by type (indemnity, IP ownership, limitation, payment terms, governing law, etc.)

2. **Cross-references three sources simultaneously:**
   - The matter's active **Playbook** — firm standard positions
   - **Prior executed contracts** in the matter and across the firm's matter history (anonymised)
   - **Case law** — relevant Indian judgments on contested clause types (from Indian Kanoon)

3. **Generates a redlined version** — track changes format, every suggested change shown inline with strikethrough (deleted) and underline (proposed)

4. **For every redline, surfaces:**
   - The **reason** — "your firm standard requires mutual indemnity. This clause is one-sided."
   - The **source** — "Razorpay-2024: you accepted this structure. Zomato-2025: you pushed back and won."
   - The **case law basis** — "SC in *Tata Consultancy v. Satyam* (23 Apr 2026): removal of cap without fresh consideration → material to bargaining fairness."
   - The **risk level** — CRITICAL / AMBER / MONITOR (colour-coded)

5. **Style matching** — if the counterparty's draft uses a particular drafting style (e.g., defined terms in ALL CAPS, numbered sub-clauses as (a)(i)), the suggested redlines match that style

6. **Re-run on demand** — "Redline against updated playbook" or "Redline as if this were a high-risk counterparty"

**Playbook feedback loop (the compounding moment):**
When a lawyer clicks `[Accept]` on any redline:
1. The redline is applied to the document


This is the lock-in. The playbook compounds. Every accepted clause makes the next redline smarter.

## PART 4 — INTELLIGENT CITATIONS (NEW OPEN FEATURE)

### What it does — full specification

Every case law reference in every document and narrative is:

1. **Automatically detected** — any citation pattern is recognised:
   - `Tata Consultancy v. Satyam Holdings (SC 2026)`
   - `AIR 1994 SC 1844`
   - `(2019) 3 SCC 457`
   - `W.P. No. 4821/2026` (High Court)
   - Informal mentions: "the Supreme Court held last week that..."

2. **Verified against Indian Kanoon** — the citation is checked. If it exists, it's linked. If it doesn't, it's flagged as unverified (hallucination prevention).

3. **The best available source is surfaced:**
   - Indian Kanoon full text (primary)
   - eCourts original order (for district/HC matters)
   - SC official website (for Supreme Court)
   - Precedence: official source > Indian Kanoon > other

4. **Citation formatted per the Indian Citation Guide** — the citation in the document/footnote follows the prescribed format:
   - SC: `Tata Consultancy Services Ltd v Satyam Computer Services Ltd, (2026) 4 SCC 112`
   - HC: `Krishnamurthy v State of Karnataka, W.P. 4821/2026 (Kar HC)`
   - Tribunal: `Sharma Textiles v. SEBI, SEBI Appellate Tribunal, 2024`

5. **Downloadable for offline attachment** — every verified citation shows a download button for the full judgment PDF, for attaching to court filings.

6. **Footnote auto-insertion** — adding a citation to a document automatically adds the formatted footnote at the bottom, numbered sequentially.

### How it appears in the demo

**In the agent narrative (MatterView):**
Every case law mention is an interactive citation chip:

> "Yesterday's `[Tata Consultancy v. Satyam ¹]` directly strengthens your position on the indemnity cap..."

The superscript `¹` links to the footnote. The chip is clickable.

**Clicking the citation chip opens a Citation Card:**

## PART 6 — REDUCE CHAT, INCREASE INLINE ACTION

### The problem
Chat as a prominent panel makes Associate look like a chatbot with a legal interface. It should look like a workspace that happens to have a chat.

### Changes to chat (from Prompt 1)

**1. Chat bubble (collapsed state) — make it smaller and less prominent:**
```css
.chat-trigger {
  width: 40px; height: 40px; /* down from 48px */
  bottom: 24px; right: 24px;
  background: var(--ink); border-radius: 50%;
  /* No label text. Just the icon. */
  opacity: 0.7; /* subtle at rest */
  transition: opacity 0.15s;
}
.chat-trigger:hover { opacity: 1; }
```

**2. In expanded state — add a matter context line:**
```
Header: "Associate" · [Varma MSA]
```
The matter context chip makes it clear this is not a generic chatbot. It is the agent of *this specific matter*.

**3. Most common chat uses should become inline actions instead:**

In the MatterView narrative, add subtle inline action links at the end of each key paragraph:
- After the indemnity paragraph: `[Draft counter →]`
- After the DPDP paragraph: `[Open draft clause →]`
- After the limitation/chronology paragraph: `[Open cross-exam questions →]`

These do what the user would have typed into chat — without typing anything. The agent has anticipated the action.

**4. The chat pre-load messages should be fewer but more proactive:**
Instead of 2 pre-loaded agent messages, show only 1 — but make it feel like the agent is *already* mid-thought:
```
[Agent — 6:12 AM]
"Read v3. Indemnity cap gone — no explanation. SC judgment from 
yesterday applies directly. Counter is ready. Want to open it or 
talk through the position first?"
```

The agent is not waiting for a question. It has already done the work and is offering options.

## THE ONE THING

If the demo does everything else right but fails to convey this, it has failed:

**The agent is not responding to the lawyer. The lawyer is arriving to find the agent's work already done.**

Every UI decision — the timeline strip, the pre-written narrative, the overnight timestamps, the redlines already loaded, the citations already verified, the brief already written — exists to create this sensation.

The lawyer is not a user. They are a partner arriving to an office where their associate worked through the night.
